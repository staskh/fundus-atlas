# Disc-and-cup benchmark — how it is run

**This page is a proposal.** Nothing has been measured yet: it sets out what the benchmark should
run on and why, so that the choice can be argued with before any of it is built. Once
`src/benchmarks/disc.py` exists, this page is generated by the run like every other configuration
page, and hand edits to it are lost.

## 1. What this benchmark asks

How close is a model's outline of the **optic disc** — the bright spot where the nerve leaves the
eye — and of the **cup** inside it to the outline an ophthalmologist drew. And, because these
structures exist to be measured rather than admired, how far that difference travels into the
numbers computed from them: the cup-to-disc ratio above all, which is what a referral decision
rests on.

Two questions, one run. A model can overlap an expert's cup by 95% and still be wrong about the
ratio, because the ratio is a quotient of two boundaries and the two errors need not cancel.

## 2. The models

Six models in this catalogue produce a disc, a cup, or both. Five can be run; one cannot.

| Model | Emits | Grid | Trained on | Mark it would carry | Run it? |
| --- | --- | --- | --- | --- | --- |
| [AutoMorph disc-and-cup](../models/automorph-disc-cup.md) | disc **and** cup | 512² → back to original | REFUGE, GAMMA | out-of-sample | **yes** |
| [SegFormer disc/cup](../models/segformer-disc-cup.md) | disc **and** cup | 512² in, 128² logits out | REFUGE | out-of-sample | **yes** |
| [BEAL](../models/beal.md) | disc **and** cup | 512² | REFUGE labelled; Drishti-GS and RIM-ONE unlabelled | out-of-sample | **yes** |
| [VascX disc](../models/vascx-disc.md) | disc only | 1024² | unpublished list | unknown | **yes**, disc tables only |
| [LUNet v2 disc](../models/lunetv2-odc.md) | disc only | 512² → back to original | **unknown** | unknown | **yes**, disc tables only |
| [ISFA](../models/isfa.md) | disc and cup | 256² | REFUGE → Drishti-GS, RIM-ONE | — | **no**: its repository ships placeholder checkpoints, not weights |

Three of the five runnable models trained on **REFUGE**, which is the pattern the quality benchmark
also found: models that share a training set agree with each other, and that agreement is not
independent evidence. It is a reason to fetch a dataset none of them saw, and to say so on every
table.

Two carry `unknown` rather than a clean mark. LUNet v2's page cannot establish what it trained on at
all, and VascX publishes no list; neither can be called out-of-sample on anything.

## 3. The datasets

### 3.1 Already in the store

| Dataset | Photographs | Disc | Cup | Readers kept apart | Notes |
| --- | --- | --- | --- | --- | --- |
| [Chákṣu](../datasets/chaksu.md) | 1,345 | ✅ | ✅ | **5 ophthalmologists** | three cameras; publishes each expert's own cup-to-disc ratio, so contours can be checked against a number the authors computed |
| [GRAPE](../datasets/grape.md) | 631 | ✅ | ✅ | 1 | the only longitudinal set here — 263 eyes over one to seven visits |
| [PAPILA](../datasets/papila.md) | 488 | ✅ | ✅ | **2 experts** | disc-centred at 30°, so the disc fills much more of the frame than in a macula-centred photograph |

**2,464 photographs, with 5, 1 and 2 readers.** That is enough to start, and Chákṣu alone makes this
the benchmark where a human ceiling can be computed properly.

[RIGA](../datasets/riga.md) is the painful exclusion: 750 photographs with **six** ophthalmologists
each, and every one of its images is a crop rather than a photograph, so the crop rule excludes it
whole. Nothing measured in pixels on a crop of a resized photograph relates to anything.

## 4. What is measured

Everything at **native resolution**, in the frame the expert drew in.

| Metric | What it says |
| --- | --- |
| **Dice**, per structure | overlap with the expert's outline — the familiar number, and the least informative here |
| **Centre offset** | between the two centroids, in pixels **and in disc diameters**, the latter being the only camera-independent form |
| **Width and height error** | signed, per structure: a model short vertically makes a vertical ratio error |
| **Equivalent radius error** | the radius of a circle of the same area, which is what most clinical software reports |
| **Vertical cup-to-disc ratio error** | signed. The number a referral rests on |
| **Area cup-to-disc ratio error** | signed, for projects that compute it that way |

**Signed, not absolute**, everywhere it can be: a model that calls every cup too large is a
different problem from one that scatters, and an absolute mean hides which you have.

## 5. The resampling path, which moves every number here

A model works on its own grid — 256, 512 or 1024 pixels square — and the expert drew on a
photograph of 1,444 to 2,576. How the first becomes the second is not a detail:

- **Probabilities are resampled to native and thresholded there**, bilinearly. Thresholding on the
  model's own grid and resampling the resulting binary mask throws away the boundary detail the
  model actually produced — and the boundary is what every metric on this page measures.
- **A binary output is resampled nearest**, and the run records that it had no better option.
- **Disc and cup are separate structures.** A cup that falls outside its own disc is measured and
  reported, never quietly repaired.

The path taken is recorded per model and appears on the results page, because two models measured
by different paths are not directly comparable.

## 6. Where a photograph is not scored

- **No contour from that reader** — nothing to score against. Counted as `excluded`, with the
  reason, never as a failure of the model.
- **Below the size floor**, 512 pixels of field, as everywhere in this repository.
- **A dataset excluded whole** by the crop rule: RIGA.
- **A finding recorded against the image** in `src/datasets/exclusions/`, which for this benchmark
  is scoped per reader — Chákṣu's three broken expert masks remove one reader's outline and leave
  the other four standing.

## 7. How it will be run

```bash
python -m benchmarks --benchmark disc
python -m benchmarks --benchmark disc --model automorph-disc-cup --dataset papila
python -m benchmarks --benchmark disc --max-samples 20
```

The predicted masks are kept in `.atlas_runs/`, unlike the quality benchmark's answers: the
biomarker benchmark's input is exactly these masks, so they are the expensive thing that must not be
thrown away.
